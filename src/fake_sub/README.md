# Fake Subscriber - RM2026 交互式数据订阅器

这是一个用于订阅和显示 RM2026 决策系统相关话题的智能调试工具，支持交互式话题选择和实时数据流监控。

## 功能特性

- **交互式选择**: 启动时可选择要监控的话题类型
- **灵活配置**: 支持预设模式和自定义选择
- **实时监控**: 订阅指定 ROS 话题并实时显示
- **TF监听**: 监听并显示坐标变换信息
- **结构化输出**: 清晰的数据格式和详细的信息显示
- **用户友好**: 简单的命令行界面，支持键盘退出

## 订阅话题

### 从 fake_publisher 订阅
- **`camera_topic`** (CameraMsg)
  - 显示相机检测到的敌方车辆信息
  - 包含位置、速度、ID等详细信息

- **`receiveLLC_pack`** (ReceiveMsg)
  - 显示裁判系统数据
  - 包含比赛状态、己方血量、弹药等

- **`navigation/status`** (Bool)
  - 显示导航完成状态反馈

- **TF变换**: `map -> base_link`
  - 显示机器人位置和姿态
  - 实时监听坐标变换

### 从 rm2026_decision 订阅
- **`navigation/goal`** (PoseStamped)
  - 显示决策系统发布的导航目标
  - 包含目标位置和时间戳

## 使用方法

### 1. 构建
```bash
cd /path/to/workspace
colcon build --packages-select fake_sub rm2026_interfaces
```

### 2. 运行
```bash
# 直接运行节点
ros2 run fake_sub fake_sub_node

# 或使用launch文件
ros2 launch fake_sub fake_sub.launch.py
```

### 3. 交互式选择
启动后会显示选择菜单：

```
=======================================
  RM2026 数据流监控器
=======================================
请选择要监控的话题类型:
1. 订阅所有话题 (ALL)
2. 只订阅相机数据 (CAMERA_ONLY)
3. 只订阅裁判系统数据 (REFEREE_ONLY)
4. 只订阅导航数据 (NAVIGATION_ONLY)
5. 只订阅TF变换 (TF_ONLY)
6. 自定义选择 (CUSTOM)
=======================================
请输入选择 (1-6):
```

选择6后会进入自定义模式：
```
自定义选择 - 选择要订阅的话题:
1. 相机数据 (/camera_topic) [y/n]: y
2. 裁判系统数据 (/receiveLLC_pack) [y/n]: n
3. 导航目标 (navigation/goal) [y/n]: y
4. 导航状态 (navigation/status) [y/n]: y
5. TF变换 (map->base_link) [y/n]: n
```

### 3. 联调测试
```bash
# 终端1：启动数据订阅器
ros2 launch fake_sub fake_sub.launch.py

# 终端2：启动假数据发布器
ros2 launch fake_publisher fake_publisher.launch.py

# 终端3：启动决策系统
ros2 launch rm2026_decision rm2026_decision.launch.py
```

## 退出方法

程序启动后，可以通过以下方式退出：

- **键盘退出**: 在终端中输入 `q` 或 `Q` 然后按 Enter
- **Ctrl+C**: 直接使用 Ctrl+C 中断程序
- **关闭终端**: 关闭运行程序的终端窗口

退出时会显示：
```
收到退出信号，正在关闭...
```

## 数据流监控

这个工具可以帮助你：

1. **验证数据发布**: 确认 fake_publisher 正常发布数据
2. **检查决策输出**: 观察 rm2026_decision 的导航决策
3. **调试TF变换**: 实时监控机器人位置信息
4. **系统联调**: 同时监控所有组件的数据流

## 故障排除

### TF查询失败
```
[INFO] TF查询失败 (这很正常，如果fake_publisher还没启动)
```
**解决方案**: 确保 fake_publisher 已启动并正在广播TF变换

### 缺少话题
如果某些话题没有收到数据，检查：
1. 对应的发布节点是否已启动
2. 话题名称是否正确
3. 网络连接是否正常

## 技术细节

- **多线程设计**: 支持并发处理多个订阅
- **异常处理**: TF查询失败时不会崩溃，只记录警告
- **性能优化**: 使用适当的队列大小和频率控制
- **实时显示**: 所有数据实时输出到控制台
